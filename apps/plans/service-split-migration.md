# Plan: shared contracts, metadata service, and service client

## Goal

Split the current single-process API into two standalone apps that talk over RPC:

- `apps/api` becomes a thin REST-to-RPC router.
- `apps/metadata` owns the database, the handlers, and validation of its own payloads.
- `packages/contracts` becomes the single authored source of the RPC schemas. It owns a sync script that copies them into each consuming app.

**Isolation principle:** apps are fully isolated environments. They have no sync script, no `predev` hook, and no reference to anything outside their own folder. Only the contracts package knows who its consumers are.

The order below keeps the API working until its replacement is proven, so there is never a moment when `metadata.*` calls have nowhere to go.

**Naming note:** the synced directory is called `src/_contracts/` in this plan (the underscore says "generated, don't edit"). It is a single constant in the sync script, so change it if you prefer another name. A tsconfig `paths` alias (e.g. `@contracts`) is a separate concern and is not needed yet.

---

## Current state

- `apps/metadata` has `src/db/` (migrations, `index.ts`, `types.ts`, `migrate.ts`), plus its own `.env`, `package.json`, `tsconfig.json`, and ESLint config. Migrations run. It has **no** server, dispatch, handlers, or contracts.
- `apps/api` still holds everything else: `contracts/`, `handlers/`, `dispatch.ts`, `errors.ts`, `routes/rpc.ts`, and the middleware. `metadata.tracks.create` is still a stub handler there.
- `packages/contracts` exists but is empty.
- The API is probably still running, since moving `db/` only breaks it if something in `apps/api` imported it. Confirm with `pnpm tsc --noEmit` in `apps/api`. If it errors, the message will point at a leftover import.

## Target state

```
packages/contracts/
  src/                          single authored source (zod schemas, FunctionName, envelope type)
  scripts/sync.mjs              copies src/ into each consumer app
apps/api/src/_contracts/        generated copy, gitignored
apps/metadata/src/_contracts/   generated copy, gitignored

apps/api:      rpc route -> router dispatch -> system.* handled locally, everything else -> service client
apps/metadata: server.ts -> dispatch (validate, run handler, validate output) -> handlers
```

## Phase 1: shared contracts and the sync script

1. **Make `packages/contracts` a slim project used only for editing and syncing**, not a package anyone installs. Give it:
   - a `package.json` with `zod` as a devDependency (the same version both apps use),
   - a `tsconfig.json` (strict, `noEmit`),
   - scripts: `"sync": "node scripts/sync.mjs"` and `"sync:watch": "node scripts/sync.mjs --watch"`.

   Without the zod devDependency your editor can't resolve `zod` when you open files in this package.
2. **Move `apps/api/src/contracts/*` into `packages/contracts/src/`** with `git mv`. Add a new `envelope.ts` with the shared response shape, exported from `index.ts`:
   ```ts
   export type Envelope<T = unknown> =
     | { ok: true; data: T }
     | { ok: false; error: { status: number; code: string; message: string; details?: unknown } };
   ```
   Both the metadata server and the API's service client need to agree on it.
3. **Write `packages/contracts/scripts/sync.mjs`**. The consumer list lives here, and nowhere else:
   ```js
   import { cpSync, rmSync, readdirSync, readFileSync, writeFileSync, watch } from "node:fs";
   import path from "node:path";
   import { fileURLToPath } from "node:url";

   const pkgRoot = path.resolve(path.dirname(fileURLToPath(import.meta.url)), "..");
   const repoRoot = path.resolve(pkgRoot, "../..");
   const SOURCE = path.join(pkgRoot, "src");
   const TARGET_DIR = "src/_contracts";
   const CONSUMERS = ["api", "metadata"];          // folder names under apps/
   const BANNER = "// GENERATED by packages/contracts/scripts/sync.mjs. Edit packages/contracts/src instead.\n";

   function stamp(dir) {
     for (const e of readdirSync(dir, { withFileTypes: true })) {
       const p = path.join(dir, e.name);
       if (e.isDirectory()) stamp(p);
       else if (p.endsWith(".ts")) writeFileSync(p, BANNER + readFileSync(p, "utf8"));
     }
   }

   function syncAll() {
     for (const app of CONSUMERS) {
       const dest = path.join(repoRoot, "apps", app, TARGET_DIR);
       rmSync(dest, { recursive: true, force: true });
       cpSync(SOURCE, dest, { recursive: true });
       stamp(dest);
       console.log(`synced contracts -> apps/${app}/${TARGET_DIR}`);
     }
   }

   syncAll();

   if (process.argv.includes("--watch")) {
     let timer;
     watch(SOURCE, { recursive: true }, () => {   // debounce: editors fire several events per save
       clearTimeout(timer);
       timer = setTimeout(syncAll, 100);
     });
     console.log("watching packages/contracts/src ...");
   }
   ```
4. **In each app**, the only change is to gitignore `src/_contracts/`. No scripts, no hooks.
5. **In the API**, change every import from `./contracts` or `../contracts` to `_contracts`.

**Check:** run `pnpm sync` in `packages/contracts`, then `pnpm tsc --noEmit` and a dev start in `apps/api`. `system.ping` works exactly as before.

**Workflow implications**
- Edit a contract in `packages/contracts/src`, then run `pnpm sync` (or leave `pnpm sync:watch` running in a terminal).
- A fresh clone needs one `pnpm sync` in `packages/contracts` before the apps will typecheck. Put this in the README, and in a root convenience command if you add one.
- CI runs the sync before typecheck.
- Edits to `src/_contracts/` in an app get overwritten. Only ever edit `packages/contracts/src`.
- Both apps must pin the same zod version, or schemas shared between them will mismatch.

## Phase 2: stand up the metadata service (copy, don't move yet)

1. In `apps/metadata`: `pnpm add zod express` and `pnpm add -D @types/express` (match the Express and zod versions the API uses). Then run `pnpm sync` in `packages/contracts` so the app gets its `_contracts` copy.
2. **Copy** `errors.ts` as is. **Copy** `handlers/types.ts` and `dispatch.ts`, changing their imports to `_contracts`. Fix the typos in the error codes: `UKNOWN_FUNCTION` is missing an N, and `"INVALID OUTPUT"` should use an underscore like the rest.
3. Write `handlers/metadata.ts` and `handlers/index.ts`. Move the stub `metadata.tracks.create` here. Type the registry as `HandlerMap<"metadata">`, not all of `FunctionName`, so it doesn't require `system.*` handlers.
4. Change `isFunctionName` in the service's dispatch to `Object.hasOwn(handlers, name)`. Otherwise `system.ping` passes the contracts check and then crashes on an undefined handler instead of returning a clean 404.
5. **Write `server.ts`**: a single `POST /rpc` route that reads `{ function, payload }` and calls `dispatch`.
   - On success send `{ ok: true, data }`.
   - Catch `AppError` and send `{ ok: false, error: { status, code, message, details } }`.
   - Anything else becomes a generic 500 error envelope.
   - Keep the HTTP status 200 for any delivered call. A failed RPC is still a successfully delivered request, and the envelope carries the error. Reserve non-200 for malformed requests.
   - **Use Express 5**, for consistency with the API. It gives JSON body parsing with a size limit for free, and the same conventions (middleware, error handling, easy `/health` later).
   - Keep the file to transport only (parse request, call `dispatch`, send envelope), so the later `lambda.ts` entry point can reuse everything else. Express never ships to Lambda.
   ```ts
   // apps/metadata/src/server.ts
   import express from "express";
   import { dispatch } from "./dispatch";
   import { AppError } from "./errors";

   const app = express();
   app.use(express.json({ limit: "1mb" }));

   app.post("/rpc", async (req, res) => {
     const { function: fn, payload } = req.body ?? {};
     try {
       res.json({ ok: true, data: await dispatch(fn, payload) });
     } catch (e) {
       if (e instanceof AppError)
         res.json({ ok: false, error: { status: e.status, code: e.code, message: e.message, details: e.details } });
       else {
         console.error(e);
         res.json({ ok: false, error: { status: 500, code: "INTERNAL", message: "Internal error" } });
       }
     }
   });

   // malformed JSON bodies never reach the route; answer with a plain 400
   app.use((err: unknown, _req: express.Request, res: express.Response, _next: express.NextFunction) => {
     res.status(400).json({ ok: false, error: { status: 400, code: "BAD_REQUEST", message: "Malformed request body" } });
   });

   app.listen(Number(process.env.METADATA_PORT ?? 4001), () => console.log("metadata service listening"));
   ```
6. Add `METADATA_PORT=4001` to `apps/metadata/.env` and `.env.example`. Since the env file lives in the app, add the dev script `tsx watch --env-file=.env src/server.ts`.

**Check:** run `pnpm dev` in `apps/metadata`, then:

```bash
curl -s -X POST localhost:4001/rpc -H 'content-type: application/json' -d '{"function":"metadata.tracks.create","payload":{"name":"x"}}'   # ok envelope
curl -s -X POST localhost:4001/rpc -H 'content-type: application/json' -d '{"function":"metadata.tracks.create","payload":{}}'             # VALIDATION_ERROR envelope
curl -s -X POST localhost:4001/rpc -H 'content-type: application/json' -d '{"function":"system.ping","payload":{}}'                         # UNKNOWN_FUNCTION envelope
```

(The `content-type` header matters, since `express.json()` only parses bodies that declare JSON. Without it `req.body` is empty and you'll get a validation error instead of the result you expect.)

The API is untouched at this point, so nothing is broken in the meantime.

## Phase 3: service client and router dispatch

1. **Write `apps/api/src/service-client.ts`.** Map the function name's prefix to a target URL (`metadata` -> `METADATA_URL`, defaulting to `http://localhost:4001/rpc`). POST `{ function, payload }` and read the envelope. On `ok: false`, throw an `AppError` built from the envelope's fields, so the existing error middleware needs no changes.
   ```ts
   const SERVICES: Record<string, string> = {
     metadata: process.env.METADATA_URL ?? "http://localhost:4001/rpc",
   };

   export const serviceClient = {
     async invoke(name: string, payload: unknown) {
       const target = SERVICES[name.split(".")[0]];
       const res = await fetch(target, {
         method: "POST",
         headers: { "content-type": "application/json" },
         body: JSON.stringify({ function: name, payload }),
         signal: AbortSignal.timeout(10_000),
       });
       const env = await res.json();
       if (!env.ok) throw new AppError(env.error.status, env.error.code, env.error.message, env.error.details);
       return env.data;
     },
   };
   ```
2. **Handle transport failures separately.** Wrap the fetch so connection errors and timeouts become `AppError(502, "SERVICE_UNAVAILABLE", ...)`. Without this, a stopped metadata service looks like an unexplained 500.
3. Add `METADATA_URL` to `apps/api/src/config.ts` and the `.env` files.
4. **Slim the API's `dispatch`** into a router:
   ```ts
   export async function dispatch(name: string, payload: unknown) {
     if (!isFunctionName(name)) throw new AppError(404, "UNKNOWN_FUNCTION", `Unknown function: ${name}`);
     if (name.startsWith("system.")) return runLocal(name, payload);  // existing validate/handle/validate path
     return serviceClient.invoke(name, payload);                      // everything else
   }
   ```
   The API does not re-validate metadata payloads. The service is the authority on its own inputs and can't trust its callers anyway.
5. **Only after step 4 is verified**, delete `apps/api/src/handlers/metadata.ts` and change the API's registry type to `HandlerMap<"system">`.

**Check:** with both processes running:
- Call the API's RPC route with `metadata.tracks.create`. You should get the stub result back.
- A bad payload should produce the same `VALIDATION_ERROR` through the API.
- Stop the metadata process. The API should return a 502 `SERVICE_UNAVAILABLE`.
- `system.ping` should still work with the metadata service off.

---

## Why this order

Moving the handlers before the client exists would leave a window where `metadata.*` calls break. Copying in phase 2 and deleting in phase 3 means there is always a working path.

## Done when

- Editing a schema in `packages/contracts/src` and running `pnpm sync` there updates both apps' types.
- Neither app contains any reference to the sync script or anything outside its own folder.
- The API contains no metadata code and no DB code.
- A `metadata.*` call goes browser -> API -> metadata -> API -> browser with errors preserved, and `system.*` calls never leave the API.

## Next after this

The real work: a `main.ts` that builds the object graph once at startup (Kysely `db`, `KyselySessionFactory`, services, handler registry via a `createMetadataHandlers(services)` factory), then the tracks slice behind the same handler names.
